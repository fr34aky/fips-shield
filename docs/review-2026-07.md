# Code review, July 2026 — outcomes and open items

A full adversarial review of the whole codebase, run across five
independent reviewers (njs engine, eBPF guard, nginx templates, shell
and fail2ban glue, tests and CI). Findings were verified against a
running stack before being acted on; a few reviewer claims did not
survive that check and are recorded below as non-findings, because
knowing what is *fine* is as useful as knowing what is broken.

Everything marked **fixed** is in commit `98eff96` and covered by a
regression test. Everything under [Open items](#open-items) is
outstanding — none of it is urgent, and none blocks deployment.

---

## Fixed: critical

### 1. Bare-LF handshake bypassed all WebSocket inspection

The sniffer in `core/njs/shield_ws.js` recognised only CRLF header
framing; nginx's HTTP parser also accepts a bare LF. A peer that ended
a header line with `\n` completed a real 101 upgrade that the engine
had classified as plain HTTP, and then spoke WebSocket with **no
message policy, no rate limits, and no mid-session ban check**. A
second variant (`\r\n\n` ending the header block) left the engine stuck
in handshake mode, forwarding ~16 KB uninspected per connection.

Verified live: a policy-denied message reached the relay through both
variants while the same message over a well-formed handshake was cut.

**Fix.** The header block is buffered whole and validated before
anything is forwarded; a bare LF is rejected outright (`protocol` /
`bare-lf-in-handshake`) rather than parsed around; and a downstream
backstop kills any session that receives a `101` the engine did not
classify as an upgrade, so a future parser divergence fails closed.
Regression test: `test/bypass_probe.py`, run by `test/ws_smoke.sh`.

### 2. Two of three fail2ban jails matched nothing

`datepattern = ^\{"ts":"{DATE}` captured the JSON prefix as group 1,
and fail2ban strips group 1 from the line before applying `failregex` —
which then required the very prefix that had been removed. The
handshake-flood and scan jails therefore matched zero lines. Only the
verdict jail ever worked, which is why the end-to-end ban test still
passed.

**Fix.** Capture only the timestamp: `^\{"ts":"({DATE})`. Because
`fail2ban-client -t` cannot catch a filter that parses but never
matches, `test/filters_test.sh` now runs `fail2ban-regex` over real log
lines and asserts the match counts. Wired into CI.

## Fixed: high

| Area | Problem | Fix |

| njs | Prototype keys defeated the caps: `["CLOSE","toString"]` drove the subscription counter negative, `["constructor",…]` passed the type allowlist | `Object.create(null)` for both sets; counter clamped at 0. Test: `test/proto_probe.py` |
| njs | Unbounded buffering — zero-length and control frames pinned a fragmented message open, growing buffers without limit | `MAX_PENDING_FRAMES` / `MAX_FRAGMENTS` caps, `frame-flood` verdict |
| nginx | `js_var` is global by name, so profiles shared one value and the last-parsed one won — enabling a second profile silently disabled the first's connection-rate limit | Policy is one string keyed by listening port (`$shield_cfg_<port>`), which cannot collide |

| eBPF | Guard stopped enforcing after a `fips` restart, raced the interface at boot, lost bans on restart, rejected fail2ban's permanent ban (`-1`) | `PartOf=fips.service`, interface wait loop, `unload` keeps pins unless `--purge`, `seconds <= 0` means permanent |
| fail2ban | `[DEFAULT]` in a `jail.d` file is global, so installing the shield silently retargeted every other jail on the host — including `sshd` | Settings repeated per jail; no `[DEFAULT]` |

## Open items

Ordered roughly by value. None is urgent.

### nginx templates

- **`server_tokens off;`** is not set, so `Server: nginx/1.29.8` and the
  version in 405/429 bodies undercut the "scanners get nothing" intent.
  One line in `core/nginx/nginx.conf`.
- **Shared `limit_conn` zones across profiles** (`shield_conn`,
  `shield_stream_conn`): a node's connections to one profile count
  against another's cap, so the tightest limit effectively governs all
  of them. Either document it or give each profile its own zone.
- **strfry passes client-supplied `X-Real-IP`, `Forwarded`,
  `CF-Connecting-IP` to the relay.** Only `X-Forwarded-For` is
  overridden, so an operator who sets strfry's `realIpHeader` to
  `x-real-ip` hands its per-IP accounting to the client. Clear the
  known set with `proxy_set_header <name> "";` in both profiles.
- **h2c upgrades are forwarded verbatim** (`Upgrade: h2c` +
  `HTTP2-Settings`). If the protected app answers 101, nginx tunnels
  and the request filter is bypassed. Map `$http_upgrade` to
  `websocket`/empty rather than echoing it.
- **The path allowlist decides on the normalised URI, but the upstream
  receives the raw one** — `/secret/../api/x` is allowed and forwarded
  as-is. Fine for apps that normalise the same way; a hazard for those
  that don't (Tomcat path parameters, frameworks routing on the raw
  string). Document, or normalise before proxying.
- **strfry's stream stage has no `limit_conn`**, unlike tcp and http;
  reads as accidental asymmetry.
- `$request` logs the query string into a volume shared with the
  fail2ban sidecar; `Host` is forwarded unvalidated with `server_name _`;
  `client_body_buffer_size` is unset so bodies spill to disk.

### njs engine

- **Mid-session ban re-check only fires on client→server activity**, so
  a peer that subscribes and then only reads is never cut. Consider
  checking on the downstream path too.
- **`loadBans()` fails open silently** on a missing/unreadable banlist
  (typo'd path, permissions) — no log, enforcement simply stops. Log
  once per transition into the failed state.
- **A corrupt banlist line reads as "not banned"** (`parseInt` → `NaN`).
- Reserved control opcodes (0xB–0xF) are forwarded rather than refused;
  a killed session never propagates EOF, lingering until
  `proxy_timeout`; `SHIELD_CONN_WINDOW=0` locks a node out permanently;
  `0` means "off" for the connection rate but "block everything" for
  the WS buckets — inconsistent knob semantics.

### eBPF guard

- **Throttle refill discards the sub-millisecond remainder**
  (`b->last_ns = now` instead of `+= elapsed_ms * 1000000`), so the
  enforced rate can be up to 2× stricter than configured. Drops
  legitimate traffic; invisible except as unexplained counts.
- **Pruning in `check`/`list` is a TOCTOU** that can delete a ban
  created concurrently by fail2ban.
- **A reload silently reuses an incompatible pinned map** — changing
  `max_entries` or the value layout is ignored rather than rejected.
  Version the pin directory or inspect `MapInfo` before reuse.
- **An evicted LRU throttle bucket resets a source's credit**; free to
  exploit on an L2 interface, expensive on `fips0`.
- `check` exits 1 both for "not banned" and for "cannot determine", so
  a broken guard looks like a clean node; `ban <ipv4>` exits 0 while
  enforcing nothing; `stats` counts expired entries; `load` resets the
  throttle config to CLI defaults.

### Detection and deployment

- **The env-file parser matches `docker run --env-file` but not
  `docker compose env_file`** — which is the mode `compose.yaml`
  actually uses. Quoted values and CRLF line endings behave differently
  between host and container mode; the in-code comment claiming the two
  agree is wrong for compose.
- **`make install` overwrites `/usr/local/bin/shield-ban`**, silently
  reverting the eBPF backend to the file backend.
- **A start-order race can destroy nginx's stdout/stderr symlinks** in
  the shared log volume (no `depends_on`), so `docker logs shield` goes
  empty and the volume grows unbounded.
- `ignoreself` protects nothing in container mode (the sidecar has no
  network, so it never sees the node's mesh address).
- `mkdir -p` in `shield-ban` inherits the caller's umask; a non-integer
  `seconds` aborts the script; `export FOO=bar` in shield.env aborts the
  installer mid-run.

### Tests and CI

- **Per-node keying has no multi-address test.** Every nginx-path test
  connects from `::1` only, so a per-node limit and a global limit are
  indistinguishable. The single largest coverage gain available: give
  the test netns two addresses.
- **Rejection helpers treat any error as success** (`refused()`,
  `expect_reject()`, `request()`): a hung or crashed shield reads as
  "correctly refused". I hit this myself while verifying a fix — a
  probe reported the rate limiter broken when the verdict log showed it
  working.
- **Ban expiry in the file backend is untested** — delete the
  `> Date.now()` comparison and everything still passes.
- Roughly half the WS violation rules have no behavioral test, notably
  `filter-complexity` (the expensive one for a relay).
- No CI `timeout-minutes`; no multi-profile *behavioral* test; njs and
  the Python helpers get no static analysis.

## Verified as fine (do not re-litigate)

- `realip` runs at `POST_READ`, before `limit_req`/`limit_conn` at
  `PREACCESS`, so the limits genuinely key on the peer's mesh address.
  Confirmed empirically with three different PROXY source addresses.
- No parser/upstream desync in the WebSocket path: forwarded bytes are
  the original masked frames, never a re-encoding.
- 64-bit lengths, fragmentation sequencing, RSV/opcode handling and
  masking are all correct; unmasking works on a copy, so the forwarded
  bytes are untouched.
- Log injection cannot fabricate a line or frame an innocent peer:
  nginx's `escape=json` escapes quotes, backslashes and control
  characters, and the regexes are anchored.
- `shield-ban`'s flock + atomic replace is correct under concurrency
  (60 parallel bans, no lost updates, no temp-file leaks).
- Source addresses on `fips0` are trustworthy: the daemon rebuilds the
  IPv6 header from the authenticated session peer, so the ban key
  cannot be spoofed.
- The BPF clock choice is right (`bpf_ktime_get_ns` and
  `CLOCK_MONOTONIC` are the same clock), and the netlink-over-TCX
  attach decision is correct for a fire-and-forget CLI.
- The ban cache genuinely persists per worker: a 20,000-entry banlist
  added no measurable per-connection latency.
